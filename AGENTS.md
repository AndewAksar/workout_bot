# AGENTS.md
# Workout Bot — техническая справка для агента

## 1. Назначение и общая логика
Workout Bot — это Telegram-бот на базе `python-telegram-bot` 22.3, который помогает пользователю вести тренировочный дневник, управлять персональными данными и синхронизироваться с сервисом Gym-Stat. Бот работает в двух режимах:

- **Локальный** — все данные (анкета, выбранные режимы) сохраняются в SQLite.
- **Интеграция Gym-Stat** — бот авторизуется в Gym-Stat по login/email/password, кэширует полученные токены и синхронизирует тренировки, группы упражнений, веса и обмеры.

Дополнительно есть виртуальный тренер с поддержкой двух моделей (ChatGPT и GigaChat), который строит ответы с учётом персональных данных пользователя.

## 2. Архитектура и ключевые компоненты
```
bot/
├─ main.py                — сборка Application и регистрация хендлеров
├─ commands/              — команды /start, /help, /contacts, /settings, /cancel, /delete_data
├─ handlers/
│   ├─ callbacks.py       — обработка inline-кнопок и переходов между состояниями
│   ├─ mode_handlers.py   — переключение режимов Local ↔ Gym-Stat и подсказки
│   ├─ api_auth.py        — мастер регистрации/логина (ConversationHandler с состояниями REG_*, LOGIN_*)
│   ├─ misc_handlers.py   — главное меню, переходы в разделы, отрисовка клавиатур
│   ├─ profile_display.py — показ данных профиля (локальных или API)
│   ├─ set_name/age/...   — функции ConversationHandler для сбора анкеты
│   ├─ body_params.py     — CRUD по обмерам тела (API или локально)
│   ├─ weight_data.py     — пагинация истории весов и добавление новых записей
│   ├─ exercises.py       — полная CRUD-логика групп и упражнений с кешированием
│   └─ workouts.py        — управление тренировками и их сетами
├─ keyboards/             — inline-клавиатуры для меню и разделов
├─ ai_assistant/          — интеграция ChatGPT и GigaChat, системный промпт
├─ api/gym_stat_client.py — асинхронный httpx-клиент для REST API Gym-Stat
├─ database/db_init.py    — создание SQLite-базы с таблицами users и UserSettings
└─ utils/                 — логирование, шифрование токенов, работа с БД, удаление сообщений, таймауты
```

### 2.1 `bot/main.py`
- Добавляет корень проекта в `sys.path`, инициализирует логгер и SQLite (через `init_db`).
- Собирает `Application` PTB, регистрирует отдельные `CommandHandler` и крупный `ConversationHandler` для многошаговых сценариев (анкета, AI, CRUD).
- Внутри `ConversationHandler` состояние определяется набором констант из `bot.config.settings` (`SET_NAME`, `SET_WEIGHT`, `WORKOUT_CREATION` и т.д.).
- Все callback-кнопки завершаются `ConversationHandler.END`, если не требуется долгого ввода текста. При входе в состояние выставляется флаг `conversation_active` в `context.user_data`.

### 2.2 Командные обработчики
- `/start` создаёт/обновляет запись в таблице `users`, показывает приветствие и клавиатуру режима.
- `/help` и `/contacts` возвращают статические подсказки, очищаемые через `schedule_message_deletion`.
- `/settings` раскрывает меню персонализации, `/cancel` прерывает активный диалог, `/delete_data` удаляет пользователя из таблиц `users` и `UserSettings`.

### 2.3 Inline-меню и вспомогательные клавиатуры
- Файлы в `bot/keyboards/` формируют `InlineKeyboardMarkup` на базе текущего режима и доступности API.
- Клавиатуры для упражнений/тренировок динамически создаются из кэша `context.user_data`, учитывают пагинацию и наличие элементов.

## 3. Персистентность и структура БД
SQLite-файл (`bot/database/users.db`) создаётся при первом запуске.

- Таблица `users`
  - `user_id` (PK) — Telegram ID.
  - `telegram_username` — username для контактов.
  - `mode` — `local` или `api`.
  - `profile_data` — JSON-поле (резерв для профиля).
  - `api_token_encrypted`, `refresh_token_encrypted` — зашифрованные токены Gym-Stat.
  - `token_expires_at` — ISO8601.
  - `created_at` — timestamp.
- Таблица `UserSettings`
  - `user_id` (PK) + поля `name`, `age`, `weight`, `height`, `gender`, `username`.

Асинхронный доступ обеспечивается через `aiosqlite` (`bot/utils/db_utils.py`).
- `get_user_mode` возвращает режим и используется в большинстве хендлеров.
- `save_api_tokens`/`get_api_tokens`/`clear_api_tokens` управляют токенами Gym-Stat.
- `api_session.get_valid_access_token` расшифровывает access token, проверяет TTL и при необходимости обновляет через `/api/users/refresh`.
- Шифрование выполняется модулем `bot/utils/encryption.py` на базе `cryptography.Fernet`, ключ хранится в `ENCRYPT_KEY`.

## 4. Режимы работы и переключение
- В `mode_handlers.py` реализованы:
  - `switch_mode_prompt` — показывает подтверждение смены режима.
  - `select_mode_local` / `select_mode_api` — обновляют запись в БД, перерисовывают главное меню.
  - `confirm_switch_mode` — обнуляет токены, если пользователь уходит из API режима.
  - `show_help` — дополнительная подсказка по режимам.
- При переключении в Gym-Stat проверяется наличие действующих токенов; если отсутствуют — предлагается зарегистрироваться или войти.
- Большинство обработчиков начинают с `mode = await get_user_mode(user_id)` и ведут себя по-разному в зависимости от режима (например, «Мои тренировки» в локальном режиме возвращают заглушку).

## 5. Сбор персональных данных (анкета)
- Callback из `callbacks.py` ставит `conversation_active` и отправляет пользователю инструкцию.
- Хендлеры `set_name`, `set_age`, `set_weight`, `set_height`, `set_gender` валидируют ввод (проверка диапазонов, конвертация чисел) и обновляют таблицу `UserSettings`.
- После успешного сохранения бот возвращает пользователя в профиль, отрисовывая актуальные данные, и планирует удаление «технических» сообщений.

## 6. Интеграция с Gym-Stat
### 6.1 Аутентификация (`handlers/api_auth.py`)
- Регистрация (состояния `REG_LOGIN`, `REG_EMAIL`, `REG_PASSWORD`, `REG_CONFIRM`): бот пошагово собирает логин, email, пароль, подтверждение, вызывает `gym_stat_client.register_user` и сообщает об успехе/ошибке.
- Логин (`LOGIN_LOGIN`, `LOGIN_PASSWORD`): бот просит логин и пароль, вызывает `login_user`, сохраняет access/refresh токены (после шифрования) и возвращает пользователя в режим API.
- При отмене (`auth_cancel`) или истечении времени (`timeout_handler`) разговор корректно завершается и клавиатуры снимаются.

### 6.2 Работа с данными
- `workouts.py`, `exercises.py`, `weight_data.py`, `body_params.py` используют `get_valid_access_token` и `gym_stat_client`.
- Все запросы логируются; если API возвращает ошибку 401, токены очищаются.
- Полученные списки кэшируются в `context.user_data` для уменьшения количества запросов при пагинации.
- Используются функции форматирования (`bot/utils/formatters.py`) для красивого отображения дат, повторов, сетов.

## 7. Управление тренировками
- `show_workouts_menu`/`show_workout_details` отображают список тренировок и детали, используя клавиатуры из `keyboards/workouts_menu.py`.
- При создании тренировки (`start_create_workout`) запускается состояние `WORKOUT_CREATION`:
  - бот запрашивает название, дату (по умолчанию — текущая), список сетов;
  - промежуточные ответы хранятся в `_WORKOUT_DRAFT_KEY` (`context.user_data`), ID технических сообщений — в `_WORKOUT_MESSAGE_IDS_KEY` для последующего удаления;
  - добавление сетов выполняется через `handle_workout_add_set_choice` и `handle_workout_exercise_selection`, где пользователь выбирает упражнение из своего каталога Gym-Stat;
  - после подтверждения бот отправляет `create_workout` и обновляет кэш.
- Удаление (`delete_workout`) требует дополнительного подтверждения с клавиатурой `get_workout_delete_keyboard`.

## 8. Управление упражнениями и группами
- `exercises.py` разбит на две крупные части: группы упражнений и сами упражнения.
- Ключевые особенности:
  - Пагинация (по 4 упражнения или 5 групп на страницу), память о текущей странице через `_EXERCISES_PAGE_KEY` и `_GROUPS_PAGE_KEY`.
  - Валидация UUID и названий, устранение HTML/Markdown через `html.escape`.
  - Выделенные ключи в `context.user_data` для черновиков (`_EXERCISE_DRAFT_KEY`, `_EXERCISE_GROUP_DRAFT_KEY`) и списков выбора.
  - Возможность переименовывать/менять описание/переносить в другую группу.
  - Удаление сопровождается клавиатурой подтверждения и отложенным удалением сообщений.

## 9. Вес и параметры тела
- `weight_data.py` отображает историю взвешиваний постранично, допускает добавление новой записи (дата + вес). При отсутствии данных показывает подсказку.
- `body_params.py` позволяет сохранить полный комплект обмеров (талия, грудь, бедра и т.п.), обновить существующие или удалить.
- Для локального режима эти разделы выводят подсказки о необходимости подключить Gym-Stat.

## 10. AI-консультант
- Меню `choose_ai_model` показывает две кнопки (ChatGPT/GigaChat) и подробное описание сценариев.
- При выборе сохраняется `context.user_data['ai_model']` и создаётся `deque(maxlen=10)` для истории.
- `handle_ai_message` формирует системный промпт (`ai_prompt.get_system_prompt`) + персональные данные (`ai_api.get_user_settings`). После каждого ответа история пополняется, что позволяет поддерживать контекст из 10 реплик.
- Ответы режутся по лимиту 4096 символов: текст разбивается прямо внутри `handle_ai_message` по границам слов, и каждая часть отправляется отдельным сообщением; клавиатура «Завершить консультацию» остаётся только под последним блоком.
- GigaChat:
  - OAuth: `ai_api.get_gigachat_token` выполняет POST на `OAUTH_URL`, передаёт `CLIENT_CREDENTIALS` (Basic) и сохраняет `access_token` в глобальной переменной.
  - Запросы (`generate_gigachat_response`) выполняются через `httpx.AsyncClient` с `verify=False`. При 401 токен перевыпускается, при 500 — экспоненциальная задержка (по умолчанию 3 попытки с шагом 2 секунды).
- ChatGPT:
  - Использует OpenAI Chat Completions (по умолчанию `gpt-4o-mini`).
  - Повторяет запрос до 3 раз, логирует ошибки, сообщает пользователю о проблемах с API.
- Завершение консультации (`end_ai_consultation`) снимает состояние, очищает историю и возвращает главное меню.

## 11. Работа с сообщениями и UX
- `bot/utils/message_deletion.schedule_message_deletion` планирует удаление служебных сообщений через `asyncio.create_task` (по умолчанию через 5 минут, в ряде сценариев — 15 секунд).
- Для предотвращения залипания клавиатур используются `edit_message_reply_markup(..., reply_markup=None)` и отдельный флаг `start_keyboard_removed`.
- `misc_handlers` отвечает за главное меню, вывод подсказок и возвращение в главное меню после любой операции.

## 12. Логирование и диагностика
- Логгер настраивается в `bot/utils/logger.py` (формат: ISO8601, уровень INFO). Все модули вызывают `setup_logging()`.
- Ошибки API и некорректный ввод пользователя логируются с уровнем WARNING/ERROR, что упрощает отладку.
- В хендлерах предусмотрены try/except, чтобы не уронить ConversationHandler (например, при ошибке Telegram API).

## 13. Рекомендации по доработке
1. При добавлении новых состояний ConversationHandler — дополнять `bot/config/settings.py` и регистрировать их в `main.py`.
2. Для новых API запросов используйте `gym_stat_client._request`, чтобы автоматически логировать ошибки и подставлять токен.
3. Соблюдайте синхронизацию `context.user_data`: очищайте черновики и временные ключи в `finally`, чтобы не мешать другим сценариям.
4. При расширении анкеты не забывайте обновлять системный промпт (`ai_prompt.py`), чтобы AI учитывал новые поля.
5. Если изменяется структура таблиц, добавляйте миграции или функции апгрейда (сейчас таблицы создаются один раз без схемы версионирования).
6. Для новых интерактивных сценариев обязательно добавляйте очистку клавиатур (`edit_message_reply_markup(None)`) и удаление сообщений, чтобы чат не захламлялся.
